Step 1: You clicked "Connect & Mint Free"
Looks like a normal NFT mint. The "zero gas" claim is the hook — it makes enabling Smart Account features sound like a benefit.
Step 2: MetaMask prompted to enable Smart Account
The dApp called wallet_sendCalls (EIP-5792). MetaMask recognizes this as a batch transaction request and shows ONE confirmation popup — which looks legitimate because it points to MetaMask's own official audited contract: EIP7702StatelessDeleGator.
Step 3: The malicious calls array
While the contract is safe, the parameters aren't. The attacker constructed this batch:
// calls array passed to wallet_sendCalls
[
  {
    to: 0xAttacker...,
    value: victimETHBalance,
    data: "0x" // direct ETH sweep
  },
  // More calls can be added here for tokens, NFTs, etc.
]
This executed atomically in one block. Your ETH balance was swept to the attacker's address before the transaction even finished.
Step 4: EOA reverted to normal
Unlike permanent EIP-7702 delegation, this batch attack is temporary. The EIP7702StatelessDeleGator bytecode was evicted from your EOA the moment the transaction ended. Your wallet looks completely normal — no approvals to revoke, no code to clear. The funds are just gone.
Step 5: Attacker launders immediately
ETH goes directly to attacker wallet. For tokens, a sweeper bot fires transferFrom() the millisecond the approval transaction confirms on-chain. By the time you open your wallet and see zero balance, the funds are already being routed through bridges and mixers.

How to stay safe

1
MetaMask only enables Smart Accounts from inside the app. If a website prompts you to "enable smart account features" or "upgrade your wallet", it's phishing. MetaMask will never ask you to do this from an external website.
2
Watch for wallet_sendCalls prompts. If MetaMask shows a batch transaction from a site you don't fully trust, reject it immediately. Check every address in the batch.
3
Use transaction simulators. Tools like Tenderly, Pocket Universe, and Revoke.cash's simulator show you exactly what a transaction will do before you confirm it.
4
"Free mint" + "zero gas" + "enable smart features" = red flag. Attackers use this combination to trick users into thinking they're getting something for free while enabling the very mechanism that drains them.
5
Revocation won't help after this attack. Because the delegation is temporary and no on-chain approvals are left behind, there's nothing to revoke. Your only protection is rejecting the transaction before it happens.
